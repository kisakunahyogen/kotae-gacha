# 答えガチャ

ニュースサイトのRSSとWikipediaから言葉を拾い、クイズの答えになりそうな「ちょっと難しい言葉」を10個ずつ引けるツールです。AI（トークン）は使いません。

## しくみ

```
GitHub Actions（1時間ごと）
  ├─ 許可リストのRSSを取得（見出しと概要だけ。記事本文は読みにいかない）
  │    └─ robots.txt で禁止されているフィードは読み飛ばす
  ├─ kuromoji で名詞・複合語を抜き出す
  ├─ Wikipedia（公式API）からも言葉を拾う
  │    ├─ 良質な記事・秀逸な記事の本文でリンクされている言葉
  │    ├─ 新しく作られた記事
  │    └─ ランダムに選ばれた記事
  ├─ 日本語版Wikipediaに記事がある言葉だけ残す
  │    （曖昧さ回避ページ・存命人物の記事は除外）
  ├─ Wikipediaの冒頭文を「意味」として保存
  ├─ Wikipediaの閲覧数で難しさを4段階に分ける
  └─ docs/words.json に書き出してコミット

GitHub Pages（docs/）
  └─ words.json を読んでガチャを回すだけの静的サイト
```

公開リポジトリにすれば、GitHub Actions も GitHub Pages も無料で使えます。

## 公開までの手順

### 0. 先にアカウントを守る（5分）

GitHub の右上のアイコン → **Settings → Password and authentication** で **2段階認証（Two-factor authentication）** をオンにします。サイトの書き換えはアカウントを乗っ取られない限り起きないので、これがいちばん効く対策です。スマホの認証アプリかパスキーを使うのがおすすめです。リカバリーコードは必ず保存してください。

### 1. リポジトリを作る

1. GitHub で新しいリポジトリを **Public（公開）** で作ります。
2. `LICENSE` の2行目「（ここにあなたの名前またはGitHubユーザー名）」を書き換えます。
3. このフォルダの中身をすべてアップロードします（`node_modules` は不要）。`.github` のように名前が「.」で始まるフォルダも忘れずに含めてください。ブラウザからアップロードする場合、隠しフォルダが表示されないことがあります。

### 2. 設定を3つ変える

1. **Settings → Pages**：Source を「Deploy from a branch」、Branch を `main`、フォルダを `/docs` にして保存します。
2. **Settings → Actions → General → Workflow permissions**：**Read and write permissions** を選んで保存します。これはクローラーが words.json をコミットするために必要です。
3. 同じ画面の **Fork pull request workflows from outside collaborators** は、初期設定のまま「承認が必要」にしておきます。知らない人の変更が勝手に実行されないようにするためです。

### 3. 初回の実行

**Actions** タブ → 左の「crawl」→「Run workflow」を押します。数分で言葉が入ります。以降は1時間ごとに自動で更新されます。サイトのURLは Settings → Pages に表示されます。

## 公開後に気をつけること

- **月に一度、Dependabot からプルリクエストが届きます。** 使っている部品の更新のお知らせです。「Files changed」を見てバージョン番号が変わっているだけなら、Merge して構いません。
- **他の人を Collaborator に追加しない。** 書き込み権限を持つ人を増やすと、その人のアカウントの安全性にも依存することになります。
- **パスワードやAPIキーをリポジトリに置かない。** このツールには不要なものです。公開リポジトリなので、置くと誰でも見られます。
- **Actions の実行ログを時々見る。** 赤い×が続いていたら、RSSのURLが変わったなどの可能性があります。

## 巡回するサイトを変える

`crawler/feeds.json` を編集します。`allowedHosts` に書いたドメインの記事だけがリンクとして採用され、それ以外のリンクは捨てられます。robots.txt で取得が禁止されているフィードは自動で読み飛ばします。ただし、利用規約までは自動で確認できません。サイトを追加するときは、そのサイトの利用規約でRSSの自動取得が認められているか、自分で確認してください。

## Wikipediaから拾う量を変える

`crawler/feeds.json` の `wikipedia` の部分で調整します。

| 設定 | 意味 |
|---|---|
| `enabled` | `false` にするとWikipediaからは拾わなくなります |
| `goodArticles.perRun` | 1回の実行で選ぶ良質な記事・秀逸な記事の数（初期値3） |
| `goodArticles.linksPerArticle` | 選んだ記事1本あたりに拾うリンク数（初期値40） |
| `newArticles.limit` | 新着記事から拾う数（初期値50） |
| `random.limit` | ランダムな記事から拾う数（初期値20、最大50） |

コトバンクは巡回対象にしていません。公開されたAPIやRSSがなく、掲載されている解説は各出版社の辞書の著作物だからです。各言葉の詳細にあるリンクから、コトバンクで調べられるようにしています。

- 詳しくは `docs/DATA-LICENSE.md` を参照してください。

## 調整できるところ（crawler/crawl.mjs の先頭）

| 設定 | 意味 |
|---|---|
| `levelOf()` | 難しさの境目（1日あたりの閲覧数）。易 2000以上 / 中 300以上 / 難 40以上 / 極 それ未満 |
| `STOP` | 候補から外すありふれた言葉 |
| `KEEP_DAYS` | 何日前のニュースの言葉まで残すか（初期値60日） |
| `MAX_LOOKUPS_PER_RUN` | 1回の実行でWikipediaに問い合わせる候補数の上限 |

## 手元で試す

```bash
npm install
npm run crawl     # RSSを読んで docs/words.json を更新
npm run serve     # http://localhost:3000 で表示
```

## 注意

- 読みは形態素解析による推定です。固有名詞では外れることがあるので、問題に使う前にリンク先で確認してください。
- GitHub Actions の定期実行は、混雑時に遅れることがあります。また、60日間リポジトリに動きがないと停止します。コミットが続いている限り止まりません。
